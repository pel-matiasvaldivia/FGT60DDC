# 09 — SMC8024L2 por interfaz web: procedimiento paso a paso

Alternativa a [`config/switches/smc8024l2-acceso.cfg`](../config/switches/smc8024l2-acceso.cfg)
para configurar los 4 switches de acceso desde el navegador.

Los nombres exactos de los menús cambian entre versiones de firmware, pero la
estructura de la interfaz Accton/SMC es siempre la misma y el **orden lógico no
cambia**: crear las VLANs → asignar los puertos → mover la gestión → guardar.

---

## 0. Antes de tocar nada

### 0.1 Reservá un puerto de rescate

**El error más común es quedarse afuera a mitad de la configuración.** Antes de
empezar, elegí un puerto por switch —por ejemplo el **23**— y dejalo **sin
tocar, en VLAN 1**, hasta el final. Es por donde vas a estar conectado.

Si en algún paso perdés el acceso: desenchufá y conectate a ese puerto.

### 0.2 Guardá la configuración actual

`System → File Management` (o `Tools → Backup`). Si no hay opción de descarga,
al menos sacá capturas de:
- `VLAN → 802.1Q VLAN → VLAN Static List`
- `VLAN → 802.1Q VLAN → VLAN Port Configuration`
- `System → IP Configuration`

### 0.3 Anotá la versión

`System → System Information` → anotá firmware y modelo exacto. Si algo no
coincide con esta guía, es el dato que necesito para corregirla.

---

## 1. Crear las VLANs

**`VLAN → 802.1Q VLAN → VLAN Static List`**

Agregá una por una (campo *VLAN ID* + *VLAN Name*, botón **Add**):

| VLAN ID | Name |
|---|---|
| 10 | USERS |
| 30 | WIFI-CORP |
| 35 | WIFI-GUEST |
| 50 | IOT-PRINT |
| 60 | MGMT |
| 999 | NATIVE-NULL |

> La VLAN 999 no transporta nada. Se usa como nativa de los enlaces entre
> switches para que ninguna trama sin etiqueta caiga en una VLAN con datos.

Verificá en **`VLAN Basic Information`** o **`Current Table`** que aparezcan las 6.

---

## 2. Asignar los puertos a cada VLAN

**`VLAN → 802.1Q VLAN → VLAN Static Table`** (en algunos firmwares,
*VLAN Static Membership by Port*).

Se elige una VLAN del desplegable y se marca, **para cada puerto**, una de tres
opciones:

| Opción | Significado |
|---|---|
| **Untagged** | El puerto pertenece a la VLAN y las tramas salen **sin** etiqueta |
| **Tagged** | El puerto pertenece a la VLAN y las tramas salen **con** etiqueta |
| **None** / *no marcado* | El puerto **no** pertenece a esa VLAN |

### 2.1 Orden que evita cortes

Para cada puerto, **primero** agregalo a su VLAN nueva y **después** sacalo de
la VLAN 1. Si lo hacés al revés, el puerto queda sin ninguna VLAN y el enlace
se corta.

### 2.2 Qué marcar en cada switch

#### SW-ACC-01

| VLAN | p1–16 (puestos) | p17–20 (AP) | p21–23 (downlinks) | p24 (uplink FGT) |
|---|---|---|---|---|
| 10 | **Untagged** | None | **Tagged** | **Tagged** |
| 30 | None | **Tagged** | **Tagged** | **Tagged** |
| 35 | None | **Tagged** | **Tagged** | **Tagged** |
| 50 | None | None | **Tagged** | **Tagged** |
| 60 | None | **Untagged** | **Tagged** | **Tagged** |
| 999 | None | None | **Untagged** | **Untagged** |
| 1 | None | None | None | None |

#### SW-ACC-02 y SW-ACC-03

| VLAN | p1–22 (puestos) | p23 (IoT) | p24 (uplink) |
|---|---|---|---|
| 10 | **Untagged** | None | **Tagged** |
| 30 / 35 / 60 | None | None | **Tagged** |
| 50 | None | **Untagged** | **Tagged** |
| 999 | None | None | **Untagged** |
| 1 | None | None | None |

#### SW-ACC-04

Igual al anterior, con **p1–20** puestos y **p21, p22, p23** en IoT (VLAN 50
Untagged).

> Recordá: el puerto de rescate que elegiste en §0.1 se deja en VLAN 1 hasta el
> final, y recién entonces se lo pasa a VLAN 10 (o 50, según corresponda).

---

## 3. Configurar el PVID de cada puerto

**`VLAN → 802.1Q VLAN → VLAN Port Configuration`**

El **PVID** define en qué VLAN cae una trama que llega **sin etiqueta**. Si el
paso 2 definió a qué VLANs pertenece el puerto, este define cuál es la suya "por
defecto".

| Tipo de puerto | PVID | Acceptable Frame Type | Ingress Filtering | GVRP |
|---|---|---|---|---|
| Puestos | **10** | All | Enabled | Disabled |
| Access points | **60** | All | Enabled | Disabled |
| Impresoras / IoT | **50** | All | Enabled | Disabled |
| Uplink y downlinks | **999** | All | Enabled | Disabled |

- **Ingress Filtering = Enabled** descarta las tramas de VLANs a las que el
  puerto no pertenece. Es lo que hace que la separación sea real.
- **GVRP = Disabled**: que las VLANs se propaguen solas suena cómodo y es una
  fuente de problemas difíciles de rastrear. Todo explícito.

---

## 4. Spanning Tree

**`Spanning Tree → STA Configuration`** (o *Spanning Tree Configuration*)

- **Spanning Tree Protocol**: `Enabled` — no lo apagues. Con 4 switches
  interconectados, un patch cord mal puesto entre dos bocas arma un bucle que
  tira la red completa.
- **Protocol Version**: `RSTP` si aparece. Si solo hay `STP`, dejalo: converge
  más lento (~30 s) pero protege igual.
- **Priority**, solo en **SW-ACC-01**: ponelo en **4096**. El switch que tiene
  el uplink al firewall debe ser la raíz del árbol; si la raíz queda en otro, el
  tráfico hacia el FortiGate da vueltas de más. Los otros tres se dejan en el
  valor por defecto (32768).

**`Spanning Tree → STA Port Configuration`**

Para los puertos de **puestos, AP e IoT** (no para uplinks ni downlinks):

- **Admin Edge Port** / *Fast Forwarding*: `Enabled`

Hace que el puerto pase a reenviar de inmediato en vez de esperar ~30 segundos
cada vez que alguien enciende su equipo.

> **Nunca** marques *Spanning Tree Disabled* en un puerto: eso no acelera nada,
> solo deja ese puerto sin protección contra bucles.

## 5. IP de gestión

**`System → IP Configuration`**

| Switch | IP Address | Subnet Mask | Gateway |
|---|---|---|---|
| SW-ACC-01 | `10.10.60.11` | `255.255.255.0` | `10.10.60.1` |
| SW-ACC-02 | `10.10.60.12` | `255.255.255.0` | `10.10.60.1` |
| SW-ACC-03 | `10.10.60.13` | `255.255.255.0` | `10.10.60.1` |
| SW-ACC-04 | `10.10.60.14` | `255.255.255.0` | `10.10.60.1` |

También: **IP Address Mode** = `Static` (no DHCP).

### 5.1 El campo que hay que buscar: Management VLAN

Buscá un campo **`Management VLAN`** o **`VLAN ID`** en esa misma pantalla (en
algunos firmwares está en `VLAN → 802.1Q VLAN → VLAN Basic Information`).

- **Si existe** → ponelo en **60**. Listo, todo según el plan.
- **Si no existe** → la gestión queda atada a la **VLAN 1** y hay que usar el
  plan alternativo de abajo. No es un problema grave, pero hay que saberlo
  **antes** de cablear.

### 5.2 Plan alternativo: gestión sin VLAN 60

Si el firmware no permite mover la gestión, la salida limpia es usar la **VLAN
sin etiqueta** como red de administración del acceso:

1. En los switches: dejá la gestión en VLAN 1 y, en el **uplink y los
   downlinks**, poné **VLAN 1 = Untagged** y **PVID = 1** (en lugar de 999).
   La VLAN 999 deja de usarse.
2. En los **puertos de AP**: PVID **1** y VLAN 1 Untagged, en lugar de la 60.
3. En el FortiGate, mové la IP de gestión del subinterfaz VLAN 60 al **puerto
   físico**:

```
config system interface
    delete "VL60-MGMT"
    edit "internal2"
        set ip 10.10.60.1 255.255.255.0
        set allowaccess ping https ssh
        set role lan
        set description "Trunk acceso + gestion sin etiqueta (VLAN nativa)"
    next
end
```

Así el tráfico **sin etiqueta** de `internal2` es la red de gestión
`10.10.60.0/24`, y los switches y AP llegan sin cambiar nada más. Las políticas
que hoy usan `VL60-MGMT` pasan a usar `internal2`.

> Los iDRAC de los nodos Proxmox cuelgan del switch **de servidores**, no de
> estos, así que no los afecta. Si estaban previstos en VLAN 60, pasalos a la
> VLAN 25, que ese switch ya transporta.

## 6. Usuarios, servicios y hora

**`Security → User Accounts`** (o `Administration → User Accounts`)

- Cambiá la contraseña por defecto del usuario `admin`.
- Si hay nivel *Guest* habilitado y no se usa, deshabilitalo.

**`System → Management` / `Security → HTTPS`**

- **HTTPS**: `Enabled`.
- **HTTP**: deshabilitalo **después** de confirmar que HTTPS funciona.
- **Telnet**: dejalo activo hasta tener SSH o HTTPS andando. Si se corta todo,
  la consola serie es la única vía.

**`System → SNTP`**

- **SNTP Client**: `Enabled`
- **Server 1**: `10.10.60.1` (el FortiGate)
- **Time Zone**: `-3` horas

Sin hora correcta, los logs del switch no sirven para nada.

---

## 7. Guardar — el paso que más se olvida

La interfaz web **aplica los cambios en caliente pero no los guarda**. Si se
corta la luz, se pierde todo y el switch arranca con la configuración anterior.

Buscá:

- `System → File Management → Copy Operation` → *Running Config* a *Startup Config*, o
- un botón **Save Configuration** / **Apply & Save** en la barra superior, o
- `Tools → Save Configuration`

**Hacelo después de cada bloque**, no solo al final.

---

## 8. Orden de trabajo recomendado

1. ⬜ Anotar firmware (§0.3) y guardar la config actual (§0.2).
2. ⬜ Elegir y reservar el puerto de rescate (§0.1).
3. ⬜ Crear las 6 VLANs (§1). **Guardar.**
4. ⬜ Asignar los puertos a las VLANs (§2). **Guardar.**
5. ⬜ Configurar los PVID (§3). **Guardar.**
6. ⬜ Spanning tree (§4). **Guardar.**
7. ⬜ Repetir 3–6 en los otros tres switches.
8. ⬜ Cablear los downlinks (p21-23 de SW-ACC-01 → p24 de los otros).
9. ⬜ Cablear p24 de SW-ACC-01 al **puerto 2 del FortiGate**.
10. ⬜ Probar con una notebook en un puerto de puestos: debe tomar
    `10.10.10.x` y navegar.
11. ⬜ Recién ahora: IP de gestión (§5) y el puerto de rescate a su VLAN final.
12. ⬜ Usuarios, HTTPS, SNTP (§6). **Guardar.**

El paso 10 antes del 11 es a propósito: si la red de puestos funciona, ya sabés
que las VLANs y el trunk están bien, y podés mover la gestión con confianza.

---

## 9. Verificación

| Pantalla | Qué mirar |
|---|---|
| `VLAN → Current Table` | Las 6 VLANs con los puertos correctos |
| `VLAN → VLAN Port Configuration` | PVID de cada puerto según §3 |
| `Spanning Tree → STA Information` | **Root Bridge = SW-ACC-01**; ningún puerto en *Blocking* que no debiera |
| `Port → Port Information` | Los enlaces entre switches en 1000 Mbps Full |
| `Address Table` | MACs de los puestos apareciendo en VLAN 10 |

Pruebas de campo:

1. Notebook en un puerto de puestos → IP `10.10.10.x`, `ping 10.10.10.1`, navega.
2. Desde la red de gestión → `ping` a `10.10.60.11` a `.14`.
3. **Prueba del bucle**: con alguien navegando, desconectá y reconectá un
   downlink. La red debe seguir. Con STP clásico puede tardar ~30 s en
   reconverger: es esperable, pero mejor verlo ahora que en producción.
4. **Prueba de aislamiento**: una notebook en un puerto de IoT (VLAN 50) **no**
   debe poder salir a internet. Si sale, revisá la política 61 del FortiGate.
